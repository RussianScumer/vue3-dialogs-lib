# Режимы окон

Каждое окно в этой библиотеке — одно и то же: сериализуемый дескриптор в сторе, отрисованный
`WindowHost` в немодальный `<dialog>`. То, что называют «режимами», — это комбинации нескольких
независимых переключателей поверх одного объекта: как окно размещено, можно ли его двигать, в какой
полосе оно рисуется и что блокирует, пока открыто.

Это руководство проходит по каждому режиму: что это, когда за ним тянуться, минимальный пример и
что переживает перезагрузку.

## Кратко

| Режим | Опция | Что блокирует | Полоса отрисовки | Сохраняется |
| --- | --- | --- | --- | --- |
| Обычное | — | ничего | `zIndexBase + z` | да |
| Ограниченное | `closable`, `minimizable`, `draggable`, `resizable` | ничего | `zIndexBase + z` | да, в дескрипторе |
| Закреплённое | `fixed: true` | ничего | `zIndexBase + topZ + z` | нет — возвращается незакреплённым |
| Лист с владельцем | `owner: id` | только своего владельца | полосу владельца, на `owner.z + 1` | никогда |
| Модальное | `modal: true` | все остальные окна, а по запросу и страницу | `zIndexBase + 3 * topZ + z` | никогда |

Два из этих переключателей — *возможности в дескрипторе*, и они сохраняются вместе с ним; остальные
живут только в рантайме, и это осознанный размен, объяснённый в разделе
[Что сохраняется, а что нет](#что-сохраняется-а-что-нет).

Они комбинируются. Окно может быть закреплённым **и** ограниченным, модальное окно может владеть
листом, а лист можно открыть над закреплённым окном. Единственная бессмысленная пара — модальное +
сворачиваемое: модальное окно принудительно несворачиваемо, потому что свёрнутое модальное окно
оставило бы рабочий стол затемнённым, и отклонять было бы нечего.

## Общая подготовка для всех примеров

```js
import { createApp } from 'vue'
import { createWindows } from '@korneevec/vue3-dialogs-lib'
import '@korneevec/vue3-dialogs-lib/style.css' // необязательная базовая таблица стилей

const components = {
  itemEditor: () => import('./windows/ItemEditor.vue'),
  logViewer: () => import('./windows/LogViewer.vue'),
  confirm: () => import('./windows/Confirm.vue'),
}

createApp(App)
  .use(createWindows({
    components,
    persist: { key: 'app:windows', storage: localStorage },
    labels: { minimize: 'Свернуть', close: 'Закрыть', pin: 'Поверх остальных' },
  }))
  .mount('#app')
```

```vue
<!-- App.vue -->
<template>
  <div class="page">
    <!-- ваше приложение -->
  </div>
  <WindowHost />
</template>
```

Монтируйте `WindowHost` **рядом** с содержимым страницы, а не внутри него. Ничто не заставляет так
делать, пока вы не начнёте использовать [модальные окна](#7--модальное), где `inert` применяется к
поддереву, — но если начать так сразу, потом не придётся ничего переносить.

Все примеры ниже предполагают `const win = useWindows()`.

## 1 · Обычное окно

Вариант по умолчанию. Перетаскивается за заголовок, меняет размер восемью ручками, сворачивается в
ваш таскбар, закрывается, примагничивается к граням экрана и сохраняется.

```js
win.open('itemEditor', { id: 42 })
```

`open()` возвращает `{ id, result }`, а не строку:

```js
const { id, result } = win.open('itemEditor', { id: 42 })
const answer = await result   // { ok: true, data } | { ok: false, reason: 'closed' | 'restored' }
```

Что вы получаете, ни о чём не прося:

| | По умолчанию |
| --- | --- |
| Размер | `640 × 480`, минимум `160 × 80`, максимума нет |
| Позиция | каскадом: `40 + (index % 8) * 28` по обеим осям |
| Наложение | `z` поднимается на `pointerdown` и при восстановлении |
| Лимит | `maxWindows: 8` — открытие девятого закрывает самое старое |
| Дедупликация | тот же тип окна + поверхностно равные props присоединяются к уже открытому окну |

Всё это переопределяется в каждом вызове:

```js
win.open('logViewer', { source: 'app' }, {
  title: 'Журнал приложения',
  x: 120, y: 80, w: 480, h: 320,
  minW: 320, minH: 200, maxH: 640,
  meta: { version: 3 },          // ваши собственные учётные данные, сохраняются вместе с окном
  dedupe: false,                 // открыть второе окно, даже если идентичное уже существует
})
```

Дедупликацию стоит понимать, потому что она включена по умолчанию: второй `open()` с тем же типом и
теми же props не открывает второе окно — он поднимает уже существующее и отдаёт вам *его* result,
поэтому оба вызывающих ждут один и тот же ответ.

Внутри собственного компонента окна:

```vue
<script setup>
import { useWindowContext, useWindowState } from '@korneevec/vue3-dialogs-lib'

const props = defineProps({ windowId: String, id: Number })
const { setTitle, resolve, dismiss, onBeforeClose } = useWindowContext()

// Черновик состояния, переживающий сворачивание (которое размонтирует этот компонент) и перезагрузку страницы.
const draft = useWindowState(props.windowId, () => ({ name: '', note: '' }))

setTitle(`Item ${props.id}`)
onBeforeClose(() => !draft.name || confirm('Отбросить черновик?'))
// resolve(value) разрешает `result` открывателя и закрывает окно.
</script>
```

## 2 · Ограниченное окно

Четыре флага возможностей выключают отдельные элементы управления. Они живут **в дескрипторе**,
поэтому сохраняются, и восстановленное окно возвращается таким же ограниченным.

```js
// Панель дашборда: фиксированная геометрия, без обвязки, убрать её может только код.
win.open('logViewer', { source: 'metrics' }, {
  x: 120, y: 120, w: 380, h: 300,
  closable: false,     // нет ✕ в заголовке
  minimizable: false,  // нет – в заголовке, и ESC больше его не сворачивает
  draggable: false,    // заголовок не перетаскивает, стрелки не двигают
  resizable: false,    // нет ручек
})
```

Каждый флаг независим — один только `resizable: false` даёт окно, которое пользователь всё ещё может
двигать и закрывать.

`closable: false` — не замок против вашего собственного кода: `win.close(id)` игнорирует и флаг, и
все guard'ы, именно поэтому на `closeAll()` при выходе из системы можно положиться. Флаг убирает
только элемент управления.

Задайте их один раз на *тип* окна, а не на вызов, зарегистрировав спецификацию:

```js
components: {
  logViewer: {
    component: () => import('./windows/LogViewer.vue'),
    w: 380, h: 300, minW: 260, minH: 180, maxH: 520,
    resizable: false,
  },
}
```

Приоритет, от самого узкого: вызов `open()` → [пресет](#9--пресеты-имя-для-режима) → спецификация
компонента → умолчание библиотеки.

## 3 · Свёрнутое

Сворачивание — это состояние в дескрипторе, а не отдельный вид окна. Содержимое
**размонтируется**, а не прячется: таймеры останавливаются, запросы не уходят, а вернуть черновик —
задача `useWindowState`.

```js
win.minimize(id)
win.restore(id)      // разворачивает и поднимает наверх
win.byId(id).minimized
win.minimized.value  // множество свёрнутых окон, для вашего таскбара
```

Библиотека не рисует таскбар. `WindowTaskbar` — renderless-компонент, разметка ваша:

```vue
<WindowTaskbar v-slot="{ all, active, restore, focus, requestClose, closing }">
  <div class="taskbar">
    <button
      v-for="w in all.filter((x) => !win.ownerOf(x.id))"
      :key="w.id"
      :class="{ active: w.id === active }"
      @click="w.minimized ? restore(w.id) : focus(w.id)"
    >
      {{ w.title || w.name }}
      <span v-if="w.closable" @click.stop="requestClose(w.id)">✕</span>
    </button>
  </div>
</WindowTaskbar>
```

Две вещи, которые стоит знать:

- **ESC сворачивает** активное окно по умолчанию. Он его не закрывает: закрытие — это решение, а
  ESC — это побег. Окно с `minimizable: false` игнорирует ESC полностью;
  [лист](#6--дочернее-окно-с-владельцем-лист) и [модальное окно](#7--модальное) им, наоборот,
  отклоняются.
- **У свёрнутого окна нет собственного guard'а закрытия**, потому что его содержимое размонтировано
  вместе с зарегистрированным им `onBeforeClose`. Остаётся только общая для приложения опция
  `beforeClose`, и она спрашивается для каждого окна.

## 4 · Примагниченное и развёрнутое

Перетащите заголовок окна к грани экрана — и оно примагнитится, как в Windows: левая или правая
грань даёт половину, угол — четверть, верх разворачивает окно. Призрак показывает превью цели, а
двойной клик по заголовку переключает разворот.

```js
const view = { w: innerWidth, h: innerHeight }

win.snap(id, 'left', view)   // 'left' | 'right' | 'max' | 'top-left' | 'top-right'
                             // | 'bottom-left' | 'bottom-right'
win.snap(id, 'none', view)   // обратно к геометрии, которая была до первого примагничивания
win.dockZone(id)             // текущая зона или null
```

Держите примагниченные окна подальше от собственной мебели интерфейса с помощью insets, а если всё
это не нужно — выключите целиком:

```js
createWindows({ components, snap: { enabled: true, edge: 12, corner: 100, insets: { bottom: 36 } } })
```

Состояние примагничивания живёт **только в рантайме**: его нет в дескрипторе и оно не сохраняется.
После перезагрузки примагниченное окно возвращается обычным плавающим окном с той геометрией,
которую дало ему примагничивание. Перетаскивание примагниченного окна прочь возвращает его
доснап-размер под курсором; изменение размера ручкой сохраняет новый размер и просто перестаёт
считать окно пристыкованным.

Клавиатурные эквиваленты включены по умолчанию — `Meta`+стрелки, плюс `Ctrl`+`Shift`+стрелки как
аккорд, переживающий настоящий оконный менеджер, — и любую привязку можно перенести или убрать через
`keymap`.

## 5 · Закреплённое (всегда сверху)

`fixed: true` открывает окно поверх всех остальных и держит его там, куда бы ни ушёл фокус.
Используйте это для мини-плеера, живого монитора, пипетки цвета — того, что должно оставаться на
виду, пока пользователь работает в окнах под ним.

```js
win.open('logViewer', { source: 'live' }, { fixed: true, w: 380, h: 240 })
```

- **Вторая полоса отрисовки.** Закреплённое окно рисуется на `zIndexBase + topZ + z`,
  незакреплённое — на `zIndexBase + z`. Поэтому любое закреплённое окно старше любого
  незакреплённого, а закреплённые окна сохраняют собственный относительный порядок. `focus()` и
  `activeId` не затрагиваются — стек по-прежнему один.
- **Инертно к геометрии.** Ни перетаскивания, ни ручек, ни сдвига стрелками, ни разворота двойным
  кликом, и `snap()` отказывает. Окно остаётся закрываемым и сворачиваемым.
- **Кнопка закрепления** появляется в заголовке после ✕ и несёт `aria-pressed`. Нажатие возвращает
  окно в обычную полосу, снова перетаскиваемым и примагничиваемым.

```js
win.isPinned(id)          // прямо сейчас в закреплённой полосе
win.isPinnable(id)        // есть что переключать — на этом рендерится кнопка в заголовке
win.setPinned(id, true)   // закрепить, сбросить примагничивание, сохранить геометрию
```

Само упоминание `fixed` и делает окно *способным* к закреплению, поэтому `fixed: false` даёт кнопку,
не начиная с закреплённого состояния, а окно, которое `fixed` вовсе не упоминает, рендерится ровно
так же, как до появления этой фичи: без лишнего элемента управления, без второй полосы.

Состояние закрепления живёт только в рантайме. Перезагрузка возвращает закреплённое окно
незакреплённым и перетаскиваемым, ровно как возвращает примагниченное окно отстыкованным:
закрепление переключает пользователь во время работы, а сохранять его означало бы двигать схему
хранилища.

## 6 · Дочернее окно с владельцем (лист)

`owner: id` открывает окно, принадлежащее другому окну. Это тот самый document-modal sheet из macOS:
оно рисуется прямо над своим владельцем, делает инертным **только этого владельца**, двигается
вместе с ним как группа и умирает вместе с ним. Все остальные окна рабочего стола остаются
полностью интерактивными, включая перетаскивание.

Тянитесь за ним, когда вопрос касается одного документа: подтверждение несохранённого черновика,
запрос переименования, пикер, принадлежащий одному редактору.

```js
// внутри собственного компонента редактора
const { windowId } = defineProps({ windowId: String })

async function ask(message) {
  const answer = await win.open('confirm', { message }, { owner: windowId }).result
  return answer.ok && answer.data
}

onBeforeClose(async () => !draft.name || (await ask('Отбросить черновик?')))
```

```vue
<!-- Confirm.vue: ответ — это собственный result окна -->
<script setup>
const { resolve } = useWindowContext()
</script>
<template>
  <button @click="resolve(false)">Продолжить правку</button>
  <button @click="resolve(true)">Отбросить</button>
</template>
```

Что библиотека устраивает за вас:

- пара двигается как группа — фокус на любом поднимает оба, а ребёнок сидит ровно на `owner.z + 1`;
- `minimize(owner)` и `requestClose(owner)` отклоняются, пока ребёнок открыт, поскольку ребёнок *и
  есть* вопрос; `close(owner)` сначала закрывает ребёнка;
- ESC отклоняет ребёнка, а не сворачивает его, а инертный владелец вообще не получает эту клавишу;
- ребёнок всегда `closable`, никогда не `minimizable`, пропускает дедупликацию, не учитывается в
  `maxWindows` и ничего не вытесняет, чтобы освободить место;
- он **никогда не сохраняется** — подтверждение не должно возвращаться после перезагрузки.

Цепочка может быть глубиной в три звена (лист может владеть листом); четвёртое бросает исключение в
`open()`, как и неизвестный id владельца.

```js
win.ownerOf(id)      // id владельца или null
win.childrenOf(id)   // живые дети, в порядке стека
win.hasChild(id)     // true, пока это окно инертно из-за собственного ребёнка
```

Таскбару обычно нужен `all.filter((w) => !win.ownerOf(w.id))`: лист принадлежит своему владельцу, а
не рабочему столу.

## 7 · Модальное

`modal: true` — версия той же идеи в масштабе рабочего стола. Окно рисуется поверх всех полос,
страница за ним приглушается затемнением, а **все остальные окна** становятся `inert`, пока оно не
закроется.

Тянитесь за ним, когда вопрос касается приложения, а не одного документа: разрушающее
подтверждение, запрос лицензии, всё, на что нужно ответить, прежде чем работа продолжится.

```js
const answer = await win.open('confirm', { message: 'Удалить 12 элементов?' }, { modal: true }).result
if (answer.ok && answer.data) await deleteItems()
```

Это по-прежнему `dialog.show()`, а не `showModal()`. Браузерного top layer нет, поэтому `zIndexBase`,
ваш таскбар, полоса закреплённых окон и анимация ухода продолжают работать — а рабочий стол без
открытых модальных окон ведёт себя ровно так же, как до того, как вы один раз воспользовались этой
опцией.

- **Третья полоса отрисовки**, выше закреплённой и выше призрака примагничивания. Лист, открытый с
  `{ owner: <это модальное окно> }`, поднимается вместе с ним; *второе* модальное окно, открытое над
  первым, приглушается им и становится инертным, как и полагается стопке диалогов.
- **Одно затемнение**, под самым верхним модальным окном. Его позиция и наложение заданы инлайново,
  поэтому оно блокирует указатель даже без импортированной таблицы стилей; оттенок задаётся
  `--vtd-scrim-bg` в необязательной таблице (`rgba(0, 0, 0, 0.4)`, темнее при
  `prefers-color-scheme: dark`). Обработчика клика на нём нет — закрытие по клику снаружи остаётся
  вашим решением.
- **Никогда не сворачивается**, принудительно, как и флаги окна с владельцем.
- **ESC отклоняет его** через `requestClose(id)`, поэтому guard закрытия всё равно отработает.
- **Никогда не сохраняется** и не переключается: модальность решается в `open()`, а модальное окно
  целиком отфильтровывается из сохранённого блоба, ровно как окно с владельцем.

```js
win.isModal(id)            // открыто как модальное
win.topModalId()           // модальное окно, под которым сидит затемнение, или null
win.isBlockedByModal(id)   // модальное окно открыто, и это окно — ни оно само, ни его ребёнок
```

### Tab не заперт

Затемнение останавливает указатель, и ничто не останавливает клавиатуру: без помощи Tab уходит из
модального окна на вашу собственную страницу. Цикл focus trap — намеренная не-цель, поэтому решение
подписное и использует тот же механизм, что и всё остальное здесь:

```js
createWindows({ components, modal: { inertRoot: '#page' } })
```

Этот элемент становится `inert`, пока открыто модальное окно, а тот `inert`, который у него уже был,
возвращается ему потом. Он **не** должен содержать `WindowHost`: `inert` покрывает поддерево,
поэтому предок окон сделал бы некликабельным само модальное окно; в dev-режиме такой элемент
вызывает предупреждение и игнорируется. Именно поэтому в
[подготовке](#общая-подготовка-для-всех-примеров) хост стоит рядом с содержимым страницы.

### Лист или модальное окно?

| | Лист — `{ owner: id }` | Модальное — `{ modal: true }` |
| --- | --- | --- |
| Область действия | одно окно: его владелец | рабочий стол |
| Что становится инертным | собственный `<dialog>` владельца | все остальные окна плюс `inertRoot`, если задан |
| Подложка | нет | одно затемнение, под верхним модальным окном |
| Другие окна | полностью рабочие, включая перетаскивание | инертны |
| Где находится | на один `z` выше владельца | верхняя полоса, выше закреплённых |
| ESC | отклоняет | отклоняет |
| Сохраняется | никогда | никогда |

Оба разрешают результат на любом пути, который их убирает, поэтому вопрос без ответа читается как
«нет», а не подвешивает вызывающего.

## 8 · Полноэкранный режим на маленьких экранах

Ниже `mobileBreakpoint` (768px по умолчанию) плавающее окно непригодно, поэтому каждое окно рисуется
как `100vw × 100dvh` с выключенными перетаскиванием, изменением размера и примагничиванием. Ничего
не запрашивается и ничего не сохраняется: геометрия дескриптора не трогается, поэтому расширение
браузера возвращает каждое окно ровно туда, где оно было.

```js
createWindows({ components, mobileBreakpoint: 768 })   // 0 отключает поведение полностью
```

Это единственный режим, на который вы не подписываетесь явно. Он комбинируется с остальными:
закреплённое окно по-прежнему сверху, модальное по-прежнему приглушает то, что за ним.

## 9 · Пресеты: имя для режима

«Режим» в вашем приложении — это обычно набор опций выше. Зарегистрируйте его один раз под именем,
вместо того чтобы повторять в каждом месте вызова:

```js
createWindows({
  components,
  presets: {
    // Классический диалог: модальный, по центру, фиксированного размера, без обвязки.
    dialog: { modal: true, placement: 'center', w: 420, h: 200,
              draggable: false, resizable: false },
    // Панель монитора: всегда сверху, маленькая, без изменения размера.
    hud: { fixed: true, w: 320, h: 180, resizable: false },
  },
})

const ok = await win.open('confirm', { message }, { preset: 'dialog' }).result
win.open('logViewer', { source: 'live' }, { preset: 'hud' })
```

Пресет назван в месте вызова, поэтому он старше собственной спецификации компонента и уступает явным
опциям этого вызова:

```
вызов open()  →  именованный пресет  →  спецификация компонента  →  умолчание библиотеки
```

Неизвестное имя пресета бросает исключение в `open()`, ровно как неизвестное имя компонента.

`placement` доступен на всех трёх уровнях:

```js
win.open('confirm', { message }, { placement: 'center', w: 400, h: 300 })
// по центру вьюпорта; 'cascade' (по умолчанию) вместо этого выкладывает лесенкой
win.open('confirm', { message }, { placement: 'center', y: 40 })
// явные x или y по-прежнему побеждают, по одной оси за раз
```

## Как выбрать между ними

| Вопрос, на который вы отвечаете | Режим |
| --- | --- |
| «Покажи этот документ или инструмент рядом с остальными» | [обычное](#1--обычное-окно) |
| «…и пользователь не должен его двигать или закрывать» | [ограниченное](#2--ограниченное-окно) |
| «Держи это на виду, пока я работаю в другом» | [закреплённое](#5--закреплённое-всегда-сверху) |
| «Ответь на это **про этот документ**, прежде чем его закрыть» | [лист с владельцем](#6--дочернее-окно-с-владельцем-лист) |
| «Ответь на это, прежде чем делать что-либо вообще» | [модальное](#7--модальное) |
| «Всегда открывай этот тип одинаково» | [пресет](#9--пресеты-имя-для-режима) или спецификация компонента |

Если хватает листа — предпочитайте его: он блокирует одно окно вместо всего рабочего стола, и
остальное приложение продолжает работать, пока пользователь думает.

## Что сохраняется, а что нет

Когда `persist` настроен, стор записывается в хранилище (отложенно, со сбросом на `pagehide`) и
читается обратно при следующей загрузке. Записывается только дескриптор.

**В дескрипторе, а значит, сохраняется:** `id`, `name`, `props`, `state` (ваш черновик из
`useWindowState`), `title`, `minimized`, `x`, `y`, `w`, `h`, `z`, `meta` и четыре флага возможностей
вместе с ограничениями размера.

**Только в рантайме, а значит, нет:**

| Состояние | Что делает перезагрузка |
| --- | --- |
| Зона примагничивания | окно возвращается плавающим, с геометрией, которую дало примагничивание |
| Закрепление (`fixed`) | возвращается незакреплённым и перетаскиваемым |
| Связь с владельцем | ребёнок **вообще не записывается** |
| Модальность | модальное окно **вообще не записывается** |
| Подписи элементов управления | перечитываются из общей опции приложения при следующей установке |
| Guard'ы закрытия, ожидающие закрытия, результаты | исчезают — результат принадлежит той загрузке страницы, которая его открыла |

Правило за этим разделением: всё, что переключается во время работы, и всё, что является *вопросом*,
остаётся вне дескриптора. Сохранение этого сдвинуло бы схему хранилища, а вопрос, возвращающийся
после перезагрузки, — это вопрос, который уже никто не задаёт.

У восстановленного окна нет живого открывателя, поэтому его результат уже разрешён:

```js
const r = await win.resultOf(id)   // { ok: false, reason: 'restored' }
win.isRestored(id)                 // true для окна, пришедшего из хранилища
```
