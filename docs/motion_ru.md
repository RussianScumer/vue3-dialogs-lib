# Анимации

Библиотека поставляет не анимацию, а конечный автомат. `WindowHost` помечает каждый кадр как
`entering`, `open` или `leaving` и держит уходящий кадр в дереве ровно столько, сколько скажет
таблица стилей; как выглядят эти три состояния, решает CSS. Никакого `<Transition>` нигде нет, и у
самого окна нет keyframes.

Именно это разделение и делает анимацию заменяемой: меняйте CSS сколько угодно, автомату всё равно —
лишь бы он по-прежнему мог прочитать с элемента одно число.

## Единственное свойство

```css
:root {
  --vtd-motion-duration: 240ms; /* базовое значение — 180ms */
}
```

`--vtd-motion-duration` — единственное пользовательское свойство, которое `style.css` *объявляет*, а
не только читает, потому что `WindowHost` должен получить значение обратно. Оно делает сразу две
вещи:

- CSS-переходы на `.vw` берут его как свою длительность;
- `durationOf()` читает его с элемента окна через `getComputedStyle` и решает, сколько держать
  уходящий кадр в дереве рендера.

Поставьте `0ms` — и окна появляются и исчезают за один кадр, ровно как без импорта стилей.
`prefers-reduced-motion: reduce` уже делает это за вас.

Объявление обёрнуто в `:where(:root)`, поэтому у него нулевая специфичность: ваш собственный `:root`,
тема-класс или инлайн-стиль на `<html>` выигрывают, и перебивать селектором ничего не нужно.

Два ограничения:

- **Потолок — 1000ms** (`MAX_LEAVING_MS` в `WindowHost.vue`). Попросите 1500ms — кадр всё равно
  снимут на 1000ms, оборвав анимацию.
- **Голое число считается миллисекундами.** `300` — невалидный CSS `<time>`, но парсер трактует его
  как `300ms`, а не держит кадр 300 секунд. `0.4s` читается как 400ms.

## Жизненный цикл

| Состояние | Ставится | Снимается |
|---|---|---|
| `entering` | при создании кадра, *до* первого рендера | на следующем кадре анимации |
| `open` | устойчивое состояние | когда окно уходит из стора |
| `leaving` | окно закрыли или свернули | через `--vtd-motion-duration` |

В DOM это `data-vw-state` на `<dialog class="vw">` окна и проп `state` у `BaseWindow` (тип
`WindowVisualState`, экспортируется).

Три следствия того, как эти состояния получаются, — и заодно причина, почему в таблице стилей
переходы, а не keyframes:

- **Появление — это *снятие* `entering` на следующем `requestAnimationFrame`.** Кадр помечается до
  первой отрисовки, поэтому есть реально отрисованное состояние, из которого можно уезжать.
- **В скрытой вкладке кадр отпускается сразу.** Фоновая вкладка ничего не рисует и не выдаёт ни
  одного кадра анимации, так что ожидание оставило бы окно в том виде, какой у `entering`, — в
  базовой таблице это «невидимо» — до тех пор, пока на вкладку не посмотрят.
- **Прерванный уход анимируется обратно.** Восстановите окно на лету — тот же кадр усыновляется
  обратно со `state = 'open'`, и текущий переход просто разворачивается. Отдельную keyframes-анимацию
  пришлось бы отменять руками.

Уходящий кадр сохраняет контент, когда *закрывается*, и теряет его, когда *сворачивается*: окно,
которое гаснет пустым, выглядит как баг, а контент свёрнутого окна размонтируется в тот же момент,
когда его свернули, — на этом и держится утверждение «свёрнутое окно ничего не стоит».

## Что делает базовая таблица

```css
.vw {
  transition:
    opacity var(--vtd-motion-duration, 0ms) ease,
    scale var(--vtd-motion-duration, 0ms) ease,
    translate var(--vtd-motion-duration, 0ms) ease;
}

.vw[data-vw-state='entering'] {
  opacity: 0;
  scale: 0.96;
}

.vw[data-vw-state='leaving'] {
  opacity: 0;
  translate: var(--vtd-min-x, 0) var(--vtd-min-y, 0);
  scale: var(--vtd-min-scale, 0.96);
}
```

**`scale` и `translate` — это отдельные CSS-свойства, и никогда не `transform`.** Собственный
`transform` кадра — это его позиция на рабочем столе, которую стор пишет инлайном; анимация
`transform` здесь перезаписала бы её, и окно прыгнуло бы в левый верхний угол. Отдельные свойства
вместо этого композируются с ней.

По той же причине никогда не кладите `transform` в `transition` на `.vw`: перетаскивание пишет
`transform` каждый кадр, и переход заставит окно отставать от указателя на кадр.

## Замена анимации

Переопределите три правила. Годится всё анимируемое, лишь бы не `transform`:

```css
:root { --vtd-motion-duration: 260ms; }

.vw[data-vw-state='entering'] {
  opacity: 0;
  scale: 1;
  translate: 0 16px;
  filter: blur(2px);
}

.vw[data-vw-state='leaving'] {
  opacity: 0;
  scale: 0.94;
  translate: 0 8px;
}
```

Если добавляете свойство, которого нет в базовом списке `transition` — как `filter` выше, — добавьте
его и в список, иначе оно будет переключаться скачком:

```css
.vw {
  transition:
    opacity var(--vtd-motion-duration) ease,
    scale var(--vtd-motion-duration) ease,
    translate var(--vtd-motion-duration) ease,
    filter var(--vtd-motion-duration) ease;
}
```

Разное сглаживание или длительность в разные стороны — обычный CSS: хост читает одно-единственное
число, поэтому держите в `--vtd-motion-duration` *самое длинное* из них, иначе кадр снимут посреди
анимации:

```css
.vw[data-vw-state='leaving'] {
  transition-timing-function: cubic-bezier(0.4, 0, 1, 1);
}
```

## Полёт в таскбар при сворачивании

Сворачивающееся окно может улетать и сжиматься к своей кнопке в таскбаре вместо того, чтобы гаснуть
на месте. На уходящий кадр инлайном ставятся три свойства:

| Свойство | Значение |
|---|---|
| `--vtd-min-x`, `--vtd-min-y` | смещение от центра самого окна к центру его кнопки в таскбаре |
| `--vtd-min-scale` | масштаб, при котором окно поместилось бы в эту кнопку |

Они появляются **только** если окно сворачивается *и* консьюмер зарегистрировал для него
прямоугольник:

```vue
<WindowTaskbar v-slot="{ all, restore, setTaskbarRect }">
  <button
    v-for="w in all"
    :key="w.id"
    :ref="(el) => setTaskbarRect(w.id, el)"
    @click="restore(w.id)"
  >
    {{ w.title }}
  </button>
</WindowTaskbar>
```

Измеряйте через ref-колбэк, как здесь, а не один раз на монтировании: так прямоугольник берётся
заново каждый раз, когда кнопка переезжает. Без зарегистрированного прямоугольника — и всегда для
*закрывающегося* окна, которому лететь не к чему — свойств нет, и фолбэки `var()` превращают правило
обратно в обычное затухание.

Чтобы оставить полёт, но поменять только масштаб:

```css
.vw[data-vw-state='leaving'] { scale: var(--vtd-min-scale, 0.8); }
```

## Затемнение под модальным окном

Скрим за модальным окном проявляется keyframes-анимацией — на том же свойстве:

```css
.vw-scrim {
  background: var(--vtd-scrim-bg, rgba(0, 0, 0, 0.4));
  animation: vw-scrim-in var(--vtd-motion-duration, 0ms) ease;
}
```

Скрим один, под самым верхним модальным окном, и размонтируется вместе с кадром этого окна — поэтому
скрим и его окно всегда уходят вместе. `--vtd-scrim-bg` меняет оттенок, не трогая проявление.

## Своя анимация для одного окна

Корневой элемент окна несёт `data-vw-state`, `data-vw-active`, `data-vw-error` и `aria-label`
(заголовок окна). Класса от консьюмера на нём нет, поэтому отдельное окно адресуется **по
заголовку**:

```css
.vw[aria-label='Журнал'] {
  --vtd-motion-duration: 450ms;
}

.vw[aria-label='Журнал'][data-vw-state='entering'] {
  opacity: 0;
  scale: 1;
  translate: 0 24px;
}

.vw[aria-label='Журнал'][data-vw-state='leaving'] {
  opacity: 0;
  scale: 0.9;
  translate: 0 24px;
}
```

Четыре вещи, которые решают, сработает это или нет:

1. **Оба атрибута в паре.** У `.vw[data-vw-state='leaving']` в `style.css` специфичность `(0,2,0)`, и
   у `.vw[aria-label='…']` сама по себе такая же — ничья, которую решает порядок таблиц. Связка двух
   атрибутов даёт `(0,3,0)` и выигрывает независимо от порядка загрузки.
2. **Длительность действительно задаётся на окно.** `durationOf()` вызывает `getComputedStyle` именно на
   этом элементе окна, так что этот кадр держится 450ms, а все остальные — глобальное значение.
3. **Не превышайте потолок в 1000ms.**
4. **Заголовок должен быть стабильным.** `setTitle()` переписывает `aria-label`, и селектор
   перестаёт совпадать.

Если заголовок динамический — пометьте корневой элемент своего компонента-контента и выбирайте кадр
через `:has()`:

```css
.vw:has([data-kind='log']) { --vtd-motion-duration: 450ms; }
```

Для открытия и закрытия это верно и **неверно для сворачивания**: контент размонтируется в том же
патче DOM, который ставит `data-vw-state='leaving'`, поэтому `:has()` перестаёт совпадать ровно в
момент старта перехода, длительность откатывается к глобальной, и кадр держится дольше, чем идёт
анимация. Для всего, что должно пережить сворачивание, берите селектор по заголовку.

## Чек-лист своей анимации

- Самая длинная длительность из всех свойств лежит в `--vtd-motion-duration`, и она ≤ 1000ms.
- Ничто не анимирует `transform`, и `transform` не входит ни в один `transition` на `.vw`.
- Каждое свойство, которое вы задаёте в `entering`/`leaving`, перечислено в `transition` на `.vw`.
- `prefers-reduced-motion: reduce` по-прежнему даёт `0ms` — если переобъявляете свойство, сохраните
  медиазапрос.
- Библиотека по-прежнему работает с полностью удалённой таблицей стилей: без анимаций, без
  удерживаемых кадров, окна появляются и исчезают за один кадр.
